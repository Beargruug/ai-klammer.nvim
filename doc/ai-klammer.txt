1. INTRODUCTION                                       *ai-klammer-introduction*

ai-klammer.nvim puts an ASCII paperclip in the bottom-right corner of your
editor. It shows up when Neovim starts with a greeting that fades after three
seconds, then stays there, blinking, until you send it away with |:Klammer|
`hide`. It watches for a few situations, says something, and offers to help.

The greeting never takes your cursor, so you can keep typing through it.

Since v0.2 it can also read your code and say something about it, see
|ai-klammer-asking|.

Fan homage, not affiliated with Microsoft.

Requires Neovim 0.10+, plus the `claude` CLI, or `curl` and an API key for
Anthropic or any OpenAI-compatible endpoint, for anything AI. `ripgrep` for
|ai-klammer-project|.

==============================================================================
2. INSTALLATION                                       *ai-klammer-installation*

With lazy.nvim: >lua

  { "Beargruug/ai-klammer.nvim", opts = { annoyance = 2 } }
<
`opts` runs |ai_klammer.setup()|. Without it the Klammer stays quiet.

3. CONFIGURATION                                     *ai-klammer-configuration*

                                                          *ai_klammer.setup()*
>lua
  require("ai_klammer").setup({
    annoyance = 2,
    language = nil,
    animate = true,
    ignore_filetypes = { "help", "qf", "netrw", "oil", "lazy", "mason",
                         "gitcommit", "TelescopePrompt", "ai_klammer" },
    git_lines = 300,
    diagnostics_count = 5,
    ai = {
      provider = "claude",
      model = nil,
      url = nil,
      api_key = nil,
      max_tokens = 1024,
      system = "You are the Klammer, ...",
      context_lines = 30,
      max_lines = 400,
      project_budget = 6000,
      blocklist = { ".env", "*.pem", "*secret*", ... },
      redact = true,
      consent = nil,
      answer_timeout = "auto",
      words_per_minute = 240,
      max_context = 150000,
      request_timeout = 60000,
    },
  })
<
annoyance ~
    0 to 3. Sets the minimum gap between quips, and how often the Klammer
    says something with no point to it at all:

        0   silent, no autocmds, no greeting, no paperclip
        1   15 minutes, jokes very rarely
        2   5 minutes, jokes rarely
        3   1 minute, jokes often

    There is no separate switch for the jokes: turning them down is turning
    the Klammer down. See the `idle` trigger in |ai-klammer-triggers|.

language ~
    "en" or "de". `nil` reads |v:lang|.

animate ~
    `true` types every quip into its bubble a few characters at a time and
    makes the Klammer hop when it starts talking. AI answers are never typed
    in, they stream in on their own. A fading bubble starts its countdown
    once the text is complete. `false` for neither.

ignore_filetypes ~
    Filetypes the Klammer stays out of. Special buffers (|'buftype'| set) are
    always skipped.

git_lines ~
    Changed lines against HEAD before the big-diff quip fires.

diagnostics_count ~
    Buffer errors before the diagnostics quip fires.

ai.provider ~
    Either the name of a module under `ai_klammer.providers.*` or your own
    table, see |ai-klammer-providers|. These ship:

        claude      the `claude` CLI, uses your Claude Code sign-in (default)
        anthropic   the Anthropic API, needs a key and `curl`
        openai      any OpenAI-compatible API, needs a key and `curl`

ai.model ~
    Model handed to the provider. `nil` takes the provider's default:
    "sonnet" for claude, "claude-sonnet-5-5" for anthropic, "gpt-4o-mini" for
    openai.

ai.url ~
    Base URL, no trailing slash. `nil` lets the provider use its own,
    `https://api.anthropic.com` for anthropic and `https://api.openai.com/v1`
    for openai. Set it to reach a proxy, a remote box or any compatible
    server, see |ai-klammer-openai|. The claude provider ignores it; it runs a
    command, not a request.

ai.api_key ~
    Read by the anthropic and openai providers, and `nil` reads the provider's
    own variable, `ANTHROPIC_API_KEY` or `OPENAI_API_KEY`. A function is called
    once per request, so the key can come out of a password manager and never
    touch your config. A plain string works and |:checkhealth| will tell you it
    is a bad idea. The claude provider needs none of this; it uses your
    existing sign-in.

ai.max_tokens ~
    Upper bound on the answer. The claude provider ignores it.

ai.system ~
    The system prompt, so the Klammer's manners are yours to change. The
    answer language is appended from `language`.

ai.context_lines ~
    Lines above and below the cursor when there is no selection and no
    enclosing function.

ai.max_lines ~
    The Klammer refuses to read a bigger range than this in one go.

ai.project_budget ~
    Roughly how many tokens of search hits |:Klammer| `project` may send,
    counted at four characters to the token. See |ai-klammer-project|.

ai.blocklist ~
    Globs for files the Klammer never reads and never mentions, see
    |ai-klammer-privacy|. A glob without a slash is matched against the file
    name, one with a slash against the whole path. Setting this replaces the
    default list rather than adding to it.

ai.redact ~
    Strip recognisable credentials out of the code before it is sent. On by
    default. See |ai-klammer-privacy|.

ai.consent ~
    `nil` asks once, before the very first request, and remembers the answer
    in the state file. `true` accepts up front, for a config that must never
    prompt. See |ai-klammer-privacy|.

ai.answer_timeout ~
    How long a finished answer stays. `"auto"` gives you six seconds plus the
    time to read it at `ai.words_per_minute`; a number is milliseconds;
    `false` keeps it until you close it. While you are in the bubble with
    |:Klammer| `focus` it never fades. The clock starts once the answer is
    complete, never while it streams.

ai.words_per_minute ~
    Your reading pace for `answer_timeout = "auto"`. Default 240, slow on
    purpose; lower it and answers stay longer, raise it and they go sooner.

ai.max_context ~
    Rough token ceiling for one conversation, at four characters to the
    token. A follow-up that would pass it starts a new conversation instead.
    Default 150000; lower it for a model with a small window.

ai.request_timeout ~
    Milliseconds without a word from the model before the Klammer hangs up
    and says so. Every piece of the answer restarts the clock, so a long
    answer that keeps coming is never cut off. Default 60000, enough for a
    model that thinks before it speaks; `false` waits forever. An unreachable
    API host fails sooner, after ten seconds, as "cannot reach".

==============================================================================
4. COMMANDS                                               *ai-klammer-commands*

                                                                    *:Klammer*
:Klammer [hello]        Greet, with a bubble.
:Klammer show           Bring the Klammer back.
:Klammer hide           Send the Klammer away for this session.
:Klammer focus          Go into the bubble, to scroll back through an answer
                        or copy from it. `q` or `<Esc>` closes it and puts the
                        cursor back where it was.
:Klammer close          Close the bubble, cancelling an answer still on its
                        way. The Klammer stays.
:Klammer last           Show the last answer again, and pick its
                        conversation back up.
:Klammer history        Pick one of the last ten answers with
                        |vim.ui.select()| and show it again.
:Klammer yank [{reg}]   Copy the last whole answer into {reg}, or into the
                        register a plain `y` would use, so 'clipboard' is
                        respected.
:Klammer reset          Forget every "never again" and reset the cooldown.
:[range]Klammer explain Explain the range, or the function around the cursor,
                        or the lines nearby. See |ai-klammer-asking|.
:[range]Klammer ask {q} Ask {q} about the same code. Without {q} it asks you
                        first through |vim.ui.input()|. Without a range,
                        after an answer, {q} is a follow-up to it. See
                        |ai-klammer-follow-up|.
:Klammer project {q}    Ask {q} about the whole repository instead of the
                        buffer. See |ai-klammer-project|. Without {q} it asks
                        you first through |vim.ui.input()|.

A bubble that asks something (a trigger, the one-time consent question) takes
the cursor, since it is waiting for a key: `y`/`j` yes, `n` no, `v`/`w` never
again for that trigger, `q` or `<Esc>` to dismiss. Everything else, answers
included, stays in the corner and leaves the cursor where it is. Answering
closes the bubble; the Klammer stays and goes back to its neutral face.

After `:Klammer hide` the next trigger brings it back. Set `annoyance = 0` for
real silence.

==============================================================================
5. TRIGGERS                                               *ai-klammer-triggers*

All triggers share one cooldown and respect "never again" individually. The
startup greeting is not a trigger: no buttons, no cooldown, no silencing.

regex ~
    |CursorHold|. A string or /slash/ literal on the cursor line with four or
    more regex metacharacters.

git ~
    |BufWritePost|. `git diff --shortstat HEAD` in the file's directory,
    run asynchronously. Fires above `git_lines` changed lines. Saying yes
    sends that diff, every changed file except those in `ai.blocklist`,
    with a `--stat` header and cut off after `ai.max_lines` lines.

diagnostics ~
    |CursorHold| and |BufWritePost|. Fires at `diagnostics_count` errors.

idle ~
    |CursorHold|. Checks nothing. Every so often the Klammer simply says
    something, and the something is of no use to anybody. This is the only
    trigger with no question behind it, so its bubble has no buttons, never
    takes your cursor and fades after four seconds on its own.

    It does not look at your code, so it sends nothing and needs no consent.
    It does look at the clock and the 'filetype': when it is past midnight,
    early morning, Monday morning, Friday after three, the weekend, more than
    two hours into the session, or a filetype it has an opinion on, half its
    remarks are about that instead. The startup greeting does the same.

    The chance comes from `annoyance`; on top of that it keeps its own
    half-hour cooldown, so a joke can never crowd out a trigger that had
    something real to say.

FACES                                                        *ai-klammer-faces*

Between bubbles the Klammer keeps a face. None of this opens a bubble, has a
cooldown, or reads your code; `annoyance = 0` turns it off with the rest.

    @  @    looking at you; blinks every two to eight seconds, sometimes twice
    ◐  ◐    the cursor is in the left third of the editor (◑  ◑ the right),
            unless 'ambiwidth' is "double", where it looks straight ahead
    ^  ^    you saved with no errors, or it finished an answer
    >  <    the error count just went up (never in insert mode)
    O  O    twenty or more lines appeared or vanished at once, or it woke up
    o  o    thinking about your question
    x  x    the request failed
    -  -    asleep after five minutes without a keypress, z's drifting up

6. ASKING                                                   *ai-klammer-asking*

What gets sent, in order:

    1. the |[range]| given to the command, so in visual mode `:Klammer explain`
       becomes `:'<,'>Klammer explain` and sends the selection
    2. the innermost function, method or class around the cursor, found with
       |treesitter|
    3. `ai.context_lines` above and below the cursor

Which of the three it was goes into the prompt as well, so the model knows
whether it is looking at a whole function or at a slice that may start
mid-expression, and does not report the cut as a bug.

An empty range or one longer than `ai.max_lines` gets a remark instead of a
request. A handy pair of maps: >lua

  vim.keymap.set({ "n", "v" }, "<leader>ke", ":Klammer explain<CR>",
    { silent = true })
  vim.keymap.set({ "n", "v" }, "<leader>ka", ":Klammer ask ", {})
  vim.keymap.set("n", "<leader>kf", "<cmd>Klammer focus<CR>")
  vim.keymap.set("n", "<leader>kc", "<cmd>Klammer close<CR>")
<
The answer streams into the bubble as it arrives and the bubble grows with it,
capped at the window height. The cursor stays where it was, so you can keep
working while it talks. |:Klammer| `focus` goes in to scroll back or copy;
the answer keeps arriving without moving your cursor, and leaving the window
any other way than `q` leaves the bubble open. Closing the bubble, `q` or
`<Esc>` in it or |:Klammer| `close` from anywhere, kills the request, so a
rambling model costs nothing. A finished answer fades on its own after a
reading time, see `ai.answer_timeout`.

Saying `y` to a trigger asks the model about what the trigger found. For the
regex trigger that is the line with the regex and three lines either side,
not the whole function. For the diagnostics trigger the error messages are
sent along with the code.

                                                       *ai-klammer-follow-up*
After an answer, `:Klammer ask` without a range continues that conversation:
the question, the code and the answer go along again, so "why?" means why
that. The answer fading away does not end it. These do:

    - `q` or `<Esc>` in the answer, or |:Klammer| `close`
    - a range, which is new code, or |:Klammer| `explain`
    - asking from another buffer than the one the conversation began in
    - the conversation passing `ai.max_context` tokens: every follow-up sends
      all of it again, so past the limit the question starts a new one

|:Klammer| `last` shows the last answer again and `history` picks one of the
last ten; either picks its conversation back up, in the buffer you are in.

Run |:checkhealth| `ai_klammer` to see which provider is active, whether its
command is on your |$PATH| and whether a key is set.

                                                        *ai-klammer-anthropic*
Claude ~

Through the `claude` CLI, if Claude Code is installed and signed in. This is
the default: no API key, it runs on your existing subscription: >lua

  require("ai_klammer").setup({})
<
That is all of it. The Klammer runs `claude --print` with its own system
prompt in place of Claude Code's, and with the file, shell and agent tools
switched off, so you get an answer and no surprises. `ai.model` takes the CLI
aliases ("sonnet", "opus", "haiku") or a full model name.

Through the API instead, with `ANTHROPIC_API_KEY` exported: >lua

  require("ai_klammer").setup({ ai = { provider = "anthropic" } })
<
or with the key fetched on demand: >lua

  ai = {
    provider = "anthropic",
    api_key = function()
      return vim.trim(vim.fn.system({ "op", "read", "op://Private/claude" }))
    end,
  }
<
Either way the selected code leaves your machine when you ask a question.
Configuring it is the consent; the Klammer will not ask again every time.

                                                           *ai-klammer-openai*
OpenAI and friends ~

The openai provider talks to anything with a `/chat/completions` endpoint, so
`ai.url` is what picks the service. The key comes from `OPENAI_API_KEY` or
from `ai.api_key`: >lua

  require("ai_klammer").setup({ ai = { provider = "openai" } })
<
Pointed somewhere else, base URL including the version segment: >lua

  -- Groq
  ai = {
    provider = "openai",
    url = "https://api.groq.com/openai/v1",
    model = "llama-3.3-70b-versatile",
  }

  -- llama.cpp or LM Studio, where the key is ignored but must not be empty
  ai = { provider = "openai", url = "http://127.0.0.1:1234/v1", api_key = "none" }
<
                                                          *ai-klammer-privacy*
What it will not send ~

The Klammer talks to a model, so your code leaves your machine when you ask
it something. Three things limit that, all on by default.

It asks once ~
    Before the very first request, the Klammer asks whether your code may be
    sent and remembers the answer. `Ne[v]er again` turns the AI features off
    for good; |:Klammer| `reset` brings them back. `ai.consent = true` skips
    the question for a config that must never prompt.

It never reads certain files ~
    Anything matching `ai.blocklist` is refused: by |:Klammer| `explain`,
    `ask` and `project`, and by the triggers, so no bubble appears in it
    offering to help. The default list covers `.env`, `.env.*`, `*.pem`,
    `*.key`, `*.p12`, `*.pfx`, `*.kdbx`, `*.tfvars`, `*secret*`,
    `*credential*`, `id_rsa*`, `id_ecdsa*`, `id_ed25519*`, `.netrc`,
    `.npmrc`, `.pypirc`, `.htpasswd`, and the `.ssh`, `.aws` and `.gnupg`
    directories.

    The refusal is silent on purpose. A Klammer that pipes up with "I will
    not read that" tells anyone looking at your screen that the file is worth
    reading.

It strips keys out of what it does send ~
    With `ai.redact`, recognisable credentials are removed from the code
    first: private key blocks, `sk-...`, `ghp_...`, `AKIA...`, `xox...`, JWTs,
    and `password = "..."`-style assignments whose value is long enough to be
    real. Known prefixes only, never an entropy guess, because a false
    positive would quietly mangle the code you asked about.

API keys reach `curl` through a `0600` file rather than the command line, so
they do not appear in `ps`.

None of this makes it safe to point the Klammer at a machine full of other
people's secrets. It narrows the obvious accidents.

                                                        *ai-klammer-providers*
Bringing your own ~

A provider is any table with a `stream` function, so which AI you use is your
decision and the Klammer never needs to know: >lua

  require("ai_klammer").setup({
    ai = { provider = { stream = function(messages, config, on_chunk, on_done)
      -- messages  { { role = "system"|"user"|"assistant",
      --               content = string }, ... }
      -- config    the resolved config, ai.model and ai.url included
      -- on_chunk  fun(text) appends to the bubble, safe from any thread
      -- on_done   fun(err|nil)
      -- return    anything with :kill(), or nil if it cannot be cancelled
    end } },
  })
<
`on_chunk` and `on_done` are already wrapped in |vim.schedule()|, so a libuv
callback can call them directly. A table without a `stream` function is
rejected in |ai_klammer.setup()|, not at the first question.

7. PROJECT QUESTIONS                                       *ai-klammer-project*

|:Klammer| `project` {q} searches the repository rather than the buffer: >

  :Klammer project why does the consent prompt fire twice
<
The content words come out of {q} — at most eight, filler words dropped — and
go to `rg` as fixed strings, up to three hits per file. The files that matched
are sent best first, together with one line naming the directories in the
repository so the model knows what kind of project it is looking at.

Best means the file matching the most *different* keywords, not the one with
the most matching lines. Counting lines puts the changelog above the code,
because prose repeats one common word while the file that owns the thing hits
several of them.

Files are added until `ai.project_budget` tokens are used up, so a question
about a very common word sends the most relevant files rather than all of
them. Overlong lines are cut at 200 characters, so one minified file cannot
take the budget on its own.

`ai.blocklist` and `ai.redact` apply here exactly as they do to the current
buffer: a hit inside a blocklisted file is dropped before anything is sent,
and keys in the matching lines are redacted.

This needs `rg` (https://github.com/BurntSushi/ripgrep) on your |$PATH|.
Without it the Klammer says so; |:checkhealth| `ai_klammer` reports it too.
`rg` honours your `.gitignore`, so build output and vendored dependencies stay
out on their own.

9. STATE                                                     *ai-klammer-state*

"Never again" choices are stored as JSON in
`stdpath("data") .. "/ai_klammer.json"`. Delete the file or run
`:Klammer reset` to start over. The cooldown lives in memory and resets with
Neovim.

Every write re-reads the file first, so two Neovims open at once do not
overwrite each other's answers.

                                                            *ai-klammer-memory*
The same file holds what the Klammer remembers about you: how many sessions
there have been, when it last saw you, how often you said no to a trigger,
and its last greeting. Counts and timestamps, nothing about your code. It
uses them to introduce itself the first time, to mark the 10th, 25th, 50th
and every hundredth session, to notice when you were gone three days or more,
to suspect your config when you restart within ten minutes, to keep score of
your noes at the same round numbers, and to never open with yesterday's
greeting. `annoyance = 0` keeps no notes at all. `:Klammer reset` leaves the
memory alone, since it is about silencing; delete the file to make it forget.

Run |:checkhealth| `ai_klammer` to see the active config and the state file.
